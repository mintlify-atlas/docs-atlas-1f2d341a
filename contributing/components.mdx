This guide provides detailed guidelines for developing high-quality, accessible, and maintainable components for the Mintlify Components library.

## Component Requirements

All components must meet these core requirements:

### Core Principles

<AccordionGroup>
  <Accordion title="Accessibility First" icon="universal-access">
    Every component must be accessible:
    - Include appropriate ARIA attributes
    - Support keyboard navigation
    - Provide clear focus indicators
    - Use semantic HTML elements
    - Test with screen readers when applicable
  </Accordion>
  
  <Accordion title="Theme Support" icon="moon">
    Components must work in both themes:
    - Support light and dark modes
    - Use CSS custom properties for theming
    - Allow overrides via Tailwind config
    - Test visual appearance in both themes
  </Accordion>
  
  <Accordion title="Performance" icon="gauge-high">
    Keep components performant:
    - Minimize re-renders with React.memo when appropriate
    - Use lazy loading for heavy dependencies
    - Avoid unnecessary DOM operations
    - Keep bundle size small
  </Accordion>
  
  <Accordion title="Documentation" icon="book">
    Comprehensive documentation is required:
    - Create Storybook stories for all variants
    - Export TypeScript types for all props
    - Add JSDoc comments for complex props
    - Include usage examples
  </Accordion>

## Component Structure

Organize your component files consistently:

```
src/components/MyComponent/
├── MyComponent.tsx        # Main component implementation
├── MyComponent.types.ts   # TypeScript interfaces (optional)
├── MyComponent.stories.tsx # Storybook stories
└── index.ts               # Re-exports
```

## TypeScript Guidelines

### Prop Types

<Note>
  Always export prop interfaces so consumers can use them for type checking and documentation.
</Note>

```tsx
// Good: Exported interface with JSDoc comments
export interface MyComponentProps {
  /**
   * The title to display
   */
  title: string;
  
  /**
   * Optional description text
   */
  description?: string;
  
  /**
   * Callback fired when clicked
   */
  onClick?: () => void;
}

// Bad: Anonymous type
const MyComponent = (props: { title: string }) => { /* ... */ };
```

### Ref Forwarding

Use `React.forwardRef` when components need to expose a ref:

```tsx
export const MyComponent = React.forwardRef<
  HTMLDivElement,
  MyComponentProps
>((props, ref) => {
  return <div ref={ref}>{/* ... */}</div>;
});

MyComponent.displayName = 'MyComponent';
```

### Generic Components

For components that work with different data types:

```tsx
export interface ListProps<T> {
  items: T[];
  renderItem: (item: T) => React.ReactNode;
}

export function List<T>({ items, renderItem }: ListProps<T>) {
  return (
    <ul>
      {items.map((item, index) => (
        <li key={index}>{renderItem(item)}</li>
      ))}
    </ul>
  );
}
```

## Styling with Tailwind CSS

### Use the `cn` Utility

Always use the `cn` utility for conditional classes:

```tsx
import { cn } from '../../utils';

<div
  className={cn(
    'base-classes',
    isActive && 'active-classes',
    isDisabled && 'disabled-classes',
    className // Allow prop overrides
  )}
/>
```

### Theme Variables

Use CSS custom properties for themeable values:

```tsx
// Use theme colors
<div className="bg-primary text-primary-foreground">

// Use semantic colors
<div className="bg-background text-foreground">
  
// Use component-specific variables
<div className="border-border rounded-radius">
```

### Dark Mode

Tailwind's dark mode is class-based. Test both themes:

```tsx
<div className="bg-white dark:bg-zinc-900 text-zinc-900 dark:text-zinc-50">
```

<Warning>
  Always test your component in both light and dark modes using Storybook's theme switcher.
</Warning>

## Accessibility Guidelines

### Keyboard Navigation

Ensure all interactive elements are keyboard accessible:

```tsx
<button
  onClick={handleClick}
  onKeyDown={(e) => {
    if (e.key === 'Enter' || e.key === ' ') {
      e.preventDefault();
      handleClick();
    }
  }}
>
  Click me
</button>
```

### ARIA Attributes

Add appropriate ARIA attributes:

```tsx
<button
  aria-label="Close dialog"
  aria-pressed={isPressed}
  aria-expanded={isExpanded}
  aria-controls="controlled-element-id"
>
```

### Focus Management

Provide clear focus indicators:

```tsx
<button className="focus:outline-none focus:ring-2 focus:ring-primary">
```

### Semantic HTML

Use appropriate HTML elements:

```tsx
// Good: Semantic elements
<nav>
  <ul>
    <li><a href="/">Home</a></li>
  </ul>
</nav>

// Bad: Divs for everything
<div>
  <div>
    <div onClick={goToHome}>Home</div>
  </div>
</div>
```

## Testing Components

### Manual Testing Checklist

Before submitting a component, test:

<Steps>
  <Step title="Visual Testing">
    - Light and dark themes
    - Different viewport sizes
    - All component variants
    - With different content lengths
  </Step>
  
  <Step title="Interaction Testing">
    - Click interactions work
    - Keyboard navigation works
    - Hover states appear correctly
    - Focus indicators are visible
  </Step>
  
  <Step title="Accessibility Testing">
    - Tab through all interactive elements
    - Use with keyboard only (no mouse)
    - Check with browser accessibility tools
    - Verify ARIA attributes are present
  </Step>
  
  <Step title="Integration Testing">
    - Works in a real application context
    - Props behave as expected
    - TypeScript types work correctly
    - No console errors or warnings
  </Step>
</Steps>

## Common Patterns

### Controlled vs Uncontrolled

Support both patterns when applicable:

```tsx
interface InputProps {
  // Controlled
  value?: string;
  onChange?: (value: string) => void;
  
  // Uncontrolled
  defaultValue?: string;
}

const Input = ({ value, onChange, defaultValue }: InputProps) => {
  const [internalValue, setInternalValue] = useState(defaultValue ?? '');
  
  const isControlled = value !== undefined;
  const currentValue = isControlled ? value : internalValue;
  
  const handleChange = (newValue: string) => {
    if (!isControlled) {
      setInternalValue(newValue);
    }
    onChange?.(newValue);
  };
  
  // ...
};
```

### Composition

Use composition for flexible components:

```tsx
// Parent component
export const Card = ({ children, className }: CardProps) => (
  <div className={cn('card-base', className)}>{children}</div>
);

// Subcomponents
export const CardHeader = ({ children, className }: CardHeaderProps) => (
  <div className={cn('card-header', className)}>{children}</div>
);

export const CardContent = ({ children, className }: CardContentProps) => (
  <div className={cn('card-content', className)}>{children}</div>
);

// Usage
<Card>
  <CardHeader>Title</CardHeader>
  <CardContent>Content</CardContent>
</Card>
```

### Render Props

For flexible rendering:

```tsx
interface ListProps<T> {
  items: T[];
  renderItem: (item: T, index: number) => React.ReactNode;
  renderEmpty?: () => React.ReactNode;
}
```

## Performance Optimization

### Memoization

Use React.memo for expensive components:

```tsx
export const ExpensiveComponent = React.memo<ExpensiveComponentProps>(
  ({ data }) => {
    // Expensive rendering
  },
  (prevProps, nextProps) => {
    // Custom comparison
    return prevProps.data.id === nextProps.data.id;
  }
);
```

### Lazy Loading

Lazy load heavy dependencies:

```tsx
import { lazy, Suspense } from 'react';

const HeavyComponent = lazy(() => import('./HeavyComponent'));

export const Parent = () => (
  <Suspense fallback={<div>Loading...</div>}>
    <HeavyComponent />
  </Suspense>
);
```

## Documentation

### JSDoc Comments

Add helpful JSDoc comments:

```tsx
/**
 * A button component that supports various styles and states.
 * 
 * @example
 * ```tsx
 * <Button variant="primary" onClick={() => alert('Clicked!')}>
 *   Click me
 * </Button>
 * ```
 */
export const Button = (props: ButtonProps) => { /* ... */ };
```

### Storybook Documentation

Use Storybook's autodocs:

```tsx
const meta: Meta<typeof MyComponent> = {
  title: 'Components/MyComponent',
  component: MyComponent,
  tags: ['autodocs'],
  parameters: {
    docs: {
      description: {
        component: 'A detailed description of what this component does.',
      },
    },
  },
};
```

## Review Checklist

Before submitting your component:

- [ ] Component works in both React 18 and 19
- [ ] Fully typed with exported TypeScript interfaces
- [ ] Supports light and dark themes
- [ ] Keyboard accessible
- [ ] ARIA attributes are present and correct
- [ ] Focus indicators are visible
- [ ] Storybook stories document all variants
- [ ] JSDoc comments explain complex props
- [ ] No linting errors (`pnpm lint:check`)
- [ ] Build succeeds (`pnpm build`)
- [ ] Follows existing code patterns
- [ ] Uses Tailwind CSS for styling
- [ ] `cn` utility used for conditional classes
- [ ] Component is exported from main index
