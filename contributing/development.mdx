This guide covers how to set up and work on Mintlify Components locally.

## Prerequisites

Before you begin, ensure you have the following installed:

- [Node.js](https://nodejs.org/) >= 20.0.0
- [pnpm](https://pnpm.io/) >= 10.0.0

<Note>
  We use pnpm as our package manager. If you don't have it installed, you can install it via npm:
  ```bash
  npm install -g pnpm
  ```
</Note>

## Getting Started

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/mintlify/components.git
    cd components
    ```
  </Step>
  
  <Step title="Install dependencies">
    ```bash
    pnpm install
    ```
    This will install all required dependencies for the project.
  </Step>
  
  <Step title="Set up pre-commit hooks">
    ```bash
    pnpm exec husky install
    ```
    This configures Git hooks to automatically run linting before each commit.
  </Step>
</Steps>

## Development Workflow

### Building

Build the component library for production:

```bash
pnpm build
```

For development with watch mode (automatically rebuilds on file changes):

```bash
pnpm dev
```

<Tip>
  Use `pnpm dev` during active development to see your changes reflected immediately.
</Tip>

### Storybook

Storybook is the primary tool for developing and previewing components. It provides an isolated environment to work on components without needing a full application.

#### Starting Storybook

Run Storybook locally:

```bash
pnpm storybook
```

This starts a local server at `http://localhost:6006` where you can view and interact with all components.

#### Building Storybook

Build Storybook for production deployment:

```bash
pnpm build-storybook
```

<Note>
  Storybook uses Tailwind CSS and PostCSS to build the stories, ensuring the development environment matches how components will look in production.
</Note>

### Linting

We use [Biome](https://biomejs.dev/) for linting and formatting.

#### Check code style

```bash
pnpm lint:check
```

#### Fix linting issues automatically

```bash
pnpm lint:fix
```

<Warning>
  Pre-commit hooks will run linting automatically before each commit. If linting fails, the commit will be rejected.
</Warning>

## Project Structure

Understanding the project structure will help you navigate the codebase:

```
packages/
└── components/          # Main component package
    ├── src/
    │   ├── components/  # React components
    │   ├── hooks/       # Custom React hooks
    │   ├── utils/       # Utility functions
    │   └── index.ts     # Package entry point
    ├── .storybook/      # Storybook configuration
    └── dist/            # Build output
```

### Key Directories

<AccordionGroup>
  <Accordion title="src/components/">
    Contains all React components. Each component typically has its own directory with:
    - Component file (`.tsx`)
    - Types file (`.types.ts`)
    - Story file (`.stories.tsx`)
  </Accordion>
  
  <Accordion title="src/hooks/">
    Custom React hooks used by components or exported for consumers.
  </Accordion>
  
  <Accordion title="src/utils/">
    Utility functions and helper modules used across the library.
  </Accordion>
  
  <Accordion title=".storybook/">
    Storybook configuration files including:
    - `main.ts` - Storybook setup
    - `preview.ts` - Global decorators and parameters
    - Theme and styling configuration
  </Accordion>
  
  <Accordion title="dist/">
    Build output directory (generated by `pnpm build`). This is what gets published to npm.
  </Accordion>
</AccordionGroup>

## Adding a New Component

<Steps>
  <Step title="Create component directory">
    Create a new directory under `packages/components/src/components/`:
    ```bash
    mkdir packages/components/src/components/MyComponent
    ```
  </Step>
  
  <Step title="Implement the component">
    Create your component file with TypeScript:
    ```tsx
    // packages/components/src/components/MyComponent/MyComponent.tsx
    import React from 'react';
    
    export interface MyComponentProps {
      // Define your props
    }
    
    export const MyComponent: React.FC<MyComponentProps> = (props) => {
      // Implement your component
    };
    ```
  </Step>
  
  <Step title="Export from index">
    Export your component from `packages/components/src/components/index.ts`:
    ```tsx
    export { MyComponent } from './MyComponent/MyComponent';
    export type { MyComponentProps } from './MyComponent/MyComponent';
    ```
  </Step>
  
  <Step title="Add Storybook story">
    Create a story file for documentation:
    ```tsx
    // packages/components/src/components/MyComponent/MyComponent.stories.tsx
    import type { Meta, StoryObj } from '@storybook/react';
    import { MyComponent } from './MyComponent';
    
    const meta: Meta<typeof MyComponent> = {
      title: 'Components/MyComponent',
      component: MyComponent,
    };
    
    export default meta;
    type Story = StoryObj<typeof MyComponent>;
    
    export const Default: Story = {
      args: {},
    };
    ```
  </Step>
  
  <Step title="Verify the build">
    Run the build to ensure everything works:
    ```bash
    pnpm build
    ```
  </Step>
</Steps>

<Tip>

</Tip>

## Code Style

Follow these conventions when writing code:

- **TypeScript** - Use TypeScript for all new code with proper type annotations
- **React patterns** - Follow existing patterns in the codebase (functional components, hooks)
- **Compatibility** - Ensure components work with React 18 and 19
- **Styling** - Use Tailwind CSS for all styling needs
- **Naming** - Use PascalCase for components, camelCase for functions and variables

## Testing Your Changes

Before submitting a PR, make sure to:

1. Run Storybook and verify your component works as expected
2. Test both light and dark themes
3. Check keyboard navigation and accessibility
4. Run `pnpm lint:check` to ensure code quality
5. Run `pnpm build` to verify the build succeeds
6. Test in both React 18 and React 19 if possible

<Warning>
  Always test your changes locally before submitting a PR. The CI pipeline will run the same checks.
</Warning>
